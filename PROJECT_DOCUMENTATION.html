1. Introduction & Objectives

1.1 Executive Summary

Campus dining facilities and local student food vendors often operate under high friction. During peak hours, students face long, unproductive queues, while vendors struggle to manage ordering queues, inventory, and bookkeeping. QuickBite resolves these friction points by providing a centralized web application.

Through a role-based environment, students can browse campus food shops, view high-definition food photos, configure a shopping cart, and place orders. Concurrently, vendors have dedicated portals to receive orders, update preparation states, manage categories/food items, and review visual dashboards containing revenue metrics and order analytics.

1.2 Core Objectives

  • Minimize Wait Times: Students can pre-order from their classes and track order preparation, picking up their meals only when they are marked "Ready".
  • Digitalize Vendor Operations: Provide local vendors with simple dashboard interfaces, eliminating paper-based logs and manual arithmetic.
  • Campus Food Discovery: Help new students discover local campus cuisines, complete with menu listings, pricing, and estimated food preparation times.
  • Establish Seamless UX: Deliver a fast-loading, single-page application feel using modern frontend routing, responsive UI layout, and clear data presentation.
Architecture Highlight

QuickBite uses Laravel 11 and Inertia.js to render a unified React (Single Page Application). All web routes are controlled by Laravel, rendering components directly without complex client-side REST state machinery.

2. System Features & User Personas

2.1 Student Customer Flow

Students represent the consumer side of the platform. Their journey is designed for speed and clarity:

  1. Landing & Search: Landing page features a prominent search bar to query specific cravings.
  2. Vendor Selection: Accessing the /browse route, students see a clean list of active vendors (e.g., Mama Titi's Kitchen, Burger Boss, Suya Spot).
  3. Menu Browsing: Selecting a vendor displays their menu items in a spacious horizontal layout (preventing vertical clustering). Each item highlights its price, ingredients, preparation time, and a matched Unsplash photo.
  4. Cart Management: Students add items, customize quantities, and view a floating cart. If they try to checkout while logged out, the system intelligently redirects them to the signup form.
  5. Order Placement & Tracking: Once checked out, the order appears on their dashboard, dynamically updating as the vendor updates the preparation status.

2.2 Food Vendor Flow

Vendors represent the business management side. Upon login, vendor profiles have access to:

  • Business Dashboard: A visual dashboard tracking two primary business health metrics:
    • Total Revenue: Total earnings aggregated from completed orders.
    • Active Orders: Count of current orders under pending, preparing, or ready states.
  • Live Order Processing: A queue displaying incoming orders where vendors can sequentially mark orders as Preparing ➔ Ready for Pickup ➔ Completed, or cancel them.
  • Menu Management: Full CRUD capabilities for their shop. Vendors can create custom food categories (e.g. "Grills", "Snacks") and add menu items with names, descriptions, prices, prep times, and custom image uploads.

3. Technology Stack & Architecture

The software architecture is structured around modern full-stack web standards, emphasizing high performance and developer velocity.

Layer Technology Function
Backend Core Laravel 11.x (PHP 8.2+) Handles routing, authentication/authorization, request validation, database interactions (Eloquent ORM), and session management.
Communication Inertia.js 2.x Bridges backend controllers and React frontend components. Sends JSON responses directly instead of traditional HTML pages or standalone REST/GraphQL endpoints.
Frontend SPA React 18.x Builds the reactive, modern user interface. Component state updates run in the client browser for an instant response feel.
Styling CSS Tailwind CSS 4.0 Utility-first framework to construct highly customized, responsive layouts. Extends with glassmorphism and animations.
Database MySQL (XAMPP environment) Relational database storage containing users, vendor profiles, categories, menu items, and order details.

3.2 Frontend Implementation & Tools Details

QuickBite's frontend utilizes a decoupled development structure compiled into static assets by Vite, and served by Laravel's routing engine. Below is the technical breakdown of the UI systems, page configurations, and libraries that form the frontend application:

1. UI Rendering Engine: React 18

React is employed to build interactive, stateful panels. It maintains internal components' local state, enabling instant updates for features such as adjusting item quantities in the shopping cart (cart state hook), filtering and search inputs, active vendor selection sidebar transitions (selectedVendor state hook), and updating order processing states without complete document reloads.

2. Development & Assets Compilation: Vite

Vite replaces legacy Webpack systems to manage hot module replacement (HMR) and assets compilation. Frontend assets, including Javascript (JSX) modules, component dependencies, SVG icons, and Tailwind stylesheets, are processed and optimized in milliseconds by Vite, resulting in zero-lag development updates and fast production bundles.

3. Frontend-Backend Connector: Inertia.js

QuickBite uses Inertia.js as a unified middleware bridge, eliminating the overhead of building independent APIs (such as REST or GraphQL configurations) and client-side routers (such as React Router). When a user navigates to a route, Laravel processes the request, loads SQL database rows, and renders the target React page dynamically by passing data variables directly as standard React props: 

// Example Laravel controller response passing data directly to React props:
return Inertia::render('Student/Browse', [
    'vendors' => $vendors
]);

4. Styling & Component Layout: Tailwind CSS & Lucide Icons

Styles are constructed using Tailwind CSS utility tokens. Custom panels are styled using absolute positions, glassmorphism filters (e.g. backdrop-blur-sm bg-white/80), and transitions. Lucide React provides clean, high-performance SVG vector icons (e.g., ShoppingCart, Star, Search, MapPin) to guide navigation across student and vendor flows.

4. Database Schema Design

QuickBite's relational database consists of 6 tables. These tables are constructed using Laravel schema migrations with foreign key constraints to ensure referential integrity.

4.1 Schema Tables Details

1. Table: users

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing unique user identifier.
name VARCHAR(255) User's display name.
email VARCHAR(255) Unique login email address.
role VARCHAR(50) User type role. Allowed values: student, vendor.
password VARCHAR(255) Hashed password string.

2. Table: vendors

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing unique vendor shop identifier.
user_id BIGINT (Foreign Key) References users.id. Cascades on delete.
name VARCHAR(255) Registered vendor shop name (e.g., Burger Boss).
description TEXT (Nullable) Tagline/description of the food shop.
is_open BOOLEAN Indicates if the shop is currently taking orders (Default: true).

3. Table: categories

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing category identifier.
vendor_id BIGINT (Foreign Key) References vendors.id. Organizes items under a specific vendor.
name VARCHAR(255) Category name (e.g. "Rice Dishes", "Drinks").

4.2 Schema Tables Details (Continued)

4. Table: menu_items

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing menu item identifier.
category_id BIGINT (Foreign Key) References categories.id. Connects item to its folder.
name VARCHAR(255) Food item name (e.g., Spicy Jollof Rice).
description TEXT (Nullable) Food item ingredients or description details.
price DECIMAL(10,2) Price of the item (stored in Naira ₦).
preparation_time INT (Nullable) Average food preparation time in minutes.
image_url VARCHAR(2048) Storage upload path or remote Unsplash image link.
is_available BOOLEAN Shows if item is in stock (Default: true).

5. Table: orders

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing unique order identifier.
user_id BIGINT (Foreign Key) References users.id (The student placing the order).
vendor_id BIGINT (Foreign Key) References vendors.id (The shop receiving the order).
total_amount DECIMAL(10,2) Total cost of the transaction.
status VARCHAR(50) Allowed states: pending, preparing, ready, completed, cancelled.

6. Table: order_items

Column Name Data Type Description / Constraints
id BIGINT (Primary Key) Auto-incrementing line item identifier.
order_id BIGINT (Foreign Key) References orders.id. Cascades on delete.
menu_item_id BIGINT (Foreign Key) References menu_items.id. Keeps record of item details.
quantity INT Quantity ordered.
price DECIMAL(10,2) Snapshot price of the item at the exact moment of checkout.

6. Concluding Remarks & Future Scope

QuickBite successfully demonstrates a modern, high-performance web platform tailored for the campus ecosystem. By adopting a monolithic SPA approach utilizing Laravel, InertiaJS, and React, the system achieves instant responsiveness without requiring complex multi-repo management.

The interface focuses heavily on user experience, adopting spacing techniques, clear indicators, responsive grid design, and clean image pairings.

6.1 Proposed Future Scope

  • Real-time WebSockets: Integrating Laravel Reverb or Pusher to push orders to the vendor dashboard and updates to students in real-time without browser reloading.
  • Payment Gateway Integration: Linking Paystack or Flutterwave payment APIs to support live student wallets and automated vendor payouts.
  • Interactive Campus Map: Implementing Leaflet.js or Google Maps API to visually display location checkpoints for vendors and students.
  • Vendor Analytics Graphs: Expanding the dashboard analytics to display line charts showing weekly or monthly revenue trends.
